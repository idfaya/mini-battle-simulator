# Buff 系统设计文档

## 1. 文档范围

- 本文档是 `MiniBattle` **Buff / 状态效果**的策划总纲：分类口径、生命周期、叠层与来源规则、跨职业核心状态的设计语义。
- 上位规则源：[`combat_system_design.md`](./combat_system_design.md)。
- 职业 Feat 与技能如何挂状态：[`roguelike_feat_skill_fill_sheet.md`](./roguelike_feat_skill_fill_sheet.md) §8。
- 静态配置 SSOT：[`config/data/buffs.json`](../config/data/buffs.json)。
- 程序实现与全表对照：[`docs/buff_system_implementation.md`](../docs/buff_system_implementation.md)、[`docs/buff_shared_table.md`](../docs/buff_shared_table.md)。

本文档定义**设计语义**；Buff ID 全集、字段现状与实现差异以 `buff_shared_table.md` 为准。

## 2. 核心原则

### 2.1 实现三层分类

| 主类型 | 含义 | 典型用途 |
| --- | --- | --- |
| `GOOD` | 增益 | 姿态、光环、资源层数、被动态标记 |
| `BAD` | 减益 | DoT、标记、软控铺垫、破甲 |
| `CONTROL` | 硬控 | 跳过本回合行动 |

设计表达可再细分为：DoT、标记、软控、硬控、姿态、光环、资源。规则分类与主类型不必一一对应。

### 2.2 叠层语义

| `stackRule` | 含义 |
| --- | --- |
| `refresh` | 重复施加时刷新持续时间；层数不变（或保持上限 1） |
| `add` | 重复施加时增加层数；常用于资源型或中毒 |

新增 Buff 必须先定：是否可叠、上限、刷新还是累加。

### 2.3 来源隔离

下列状态**必须**记录施法者（`caster`），同目标可被不同来源各自维持：

- 点燃 / 燃烧
- 霜冻
- 猎人印记
- 静电印记

同来源重复施加只刷新持续或层数，**不**生成第二个并行实例。多同职业并存时，禁止互相覆盖或重复兑现。

### 2.4 硬控与软控

| 类型 | 是否跳过行动 | 示例 |
| --- | --- | --- |
| 硬控 | 是 | `冻结（880002）`、`眩晕（880003）` |
| 软控 / 铺垫 | 否 | `霜冻（880005）`、`减速（880001）` |

`霜冻` 的语义是**无法移动，但仍可远程攻击和施法**；只有转入 `冻结` 后才阻断行动。

### 2.5 配置与逻辑分工

- Buff 配置承载：ID、名称、主类型、持续、叠层、`value`、内建 `effects`。
- 技能链路承载：施加条件、联动兑现、引爆、驱散、Feat 修改。
- 不要把完整技能收益写进 Buff 配置；复杂规则放在 `skills/` 封装或时间线标签。

## 3. 生命周期与结算时机

```text
技能 / 被动命中
→ ApplyBuffFromSkill（挂载）
→ ON_ADD（属性挂载、惩罚施加等）
→ … 单位行动 …
→ 目标回合开始 → ON_ROUND_BEGIN（DoT、燃烧豁免等）
→ …
→ 回合结束 → duration 递减
→ ON_REMOVE（还原属性等）
```

| 时机 | 设计用途 |
| --- | --- |
| `ON_ADD` | 挂载 AC / 豁免惩罚、标记机会消耗位 |
| `ON_ROUND_BEGIN` | DoT 跳伤、燃烧反射豁免 |
| `ON_ROUND_END` | 少数持续性收尾（当前工程较少使用） |
| `ON_REMOVE` | 还原 ON_ADD 改过的属性 |

持续回合以「挂载当回合计入」为默认理解；永久态（`isPermanent = true`）不因 `duration` 字段自然消失。

## 4. 跨职业核心状态

以下状态是职业主轴的策划 SSOT；Feat 节点数值见 `roguelike_feat_skill_fill_sheet.md` §8。

### 4.1 燃烧（`870001`）

| 项 | 规则 |
| --- | --- |
| 施加 | 火焰法术**命中**后挂载（`余烬点燃`）；伤害结算完成后施加 |
| 持续 | 默认 `2` 回合；施法者带 `火焰亲和（870002）` +1 回合；`dotDurationDelta` 可再延长 |
| 叠层 | 不可叠；已燃烧只刷新持续 |
| 结算 | **每回合开始**反射豁免（对施法者 `spellDC`）；**成功移除**，**失败 `1d4` 火伤并继续** |
| 联动 | `灰烬爆燃` / `烈焰风暴`：已燃烧 `+1d8` 并刷新 / 延长；未燃烧则点燃 |

### 4.2 霜冻（`880005`）与冻结（`880002`）

| 项 | 霜冻 | 冻结 |
| --- | --- | --- |
| 施加 | 寒霜法术命中后（`寒霜迟滞`） | `冻结新星` 对已霜冻目标转化 |
| 持续 | 默认 `2` 回合；`dotDurationDelta` 可延长 | `1` 回合 |
| 语义 | 无法移动；**不**阻断远程攻击与施法 | 硬控，跳过行动 |
| 叠层 | 不可叠；只刷新 | 不可叠；只刷新 |
| 联动 | `暴风雪`：已霜冻 `+1d8` 并刷新；未霜冻只挂霜冻 | `冻结精通` 等对 `FROZEN` 目标追加收益 |

霜冻与燃烧一样带来源隔离；不与邪术师印记共用来源语义。

### 4.3 猎人印记（`890005`）

| 项 | 规则 |
| --- | --- |
| 施加 | 每回合 `1` 次；远程基础攻击**命中**后（与最终伤害是否 `> 0` 无关） |
| 持续 | 默认 `2` 回合；`dotDurationDelta` 可延长 |
| 槽位 | 默认同游侠 `1` 个；`markSlotMax` 可扩至 `2` |
| 减益 | AC 与反射豁免各 `-N`；`N` 基础 `1`，由 `value` 承载，Feat 可加深 |
| 联动 | `狩猎指引`、`箭雨`、印记大师等只服务**已被你标记**的目标 |

细则见 `roguelike_feat_skill_fill_sheet.md` §8.4。

### 4.4 静电印记（`890001`）

| 项 | 规则 |
| --- | --- |
| 施加 | `邪能冲击` 命中后；同来源只刷新持续 |
| 持续 | 默认 `2` 回合 |
| 兑现 | 邪能冲击 / 雷链命中已标记者追加雷伤；**不移除**印记 |
| 引爆 | `雷暴` 命中已标记者 `+1d8` 并**清除**印记；未标记者只挂印记 |
| 次数 | `markRecastPerRound`、`markPayoutPerRound` 由 Feat 控制上印记与兑现频率 |

不与法师霜冻、术士燃烧共享来源或减速语义。

### 4.5 中毒（`850001`）

| 项 | 规则 |
| --- | --- |
| 定位 | 毒系 DoT 资源，可叠层引爆 |
| 叠层 | 可叠至 `99` 层；`add` 规则 |
| 结算 | 每回合开始按层数造成 `Xd4` 毒伤（`X = 层数`） |
| 联动 | 可被毒爆类技能引爆并清空层数；可被净化 |

当前无独立 Feat 树章节；数值与技能落点以技能配置与实现为准。

## 5. 通用减益与控制

| Buff ID | 名称 | 设计语义 |
| --- | --- | --- |
| `880001` | 减速 | 软控；AC 与反射豁免下降；参与速度百分比计算，**不改变行动频率** |
| `880004` | 破绽 | `AC -1`，持续 `1` 回合 |
| `890014` | 重击破绽 | 自损型破绽；`AC -2`，持续 `1` 回合 |
| `880003` | 眩晕 | 硬控 `1` 回合；满足偷袭等失能判定 |
| `880006` | 盲目 | 诡诈打击附加负面；持续 `1` 回合 |
| `880007` | 流血 | 物理创伤标记；可放宽盗贼偷袭触发 |
| `820001` | 挑衅 | 目标约束标记；强制目标逻辑在技能侧 |

## 6. 姿态 / 光环 / 资源类

此类 Buff 多为**标记 + 外部读取**，收益由被动或技能在命中、受击、回合钩子中兑现。

| 分类 | 代表 Buff | 用途摘要 |
| --- | --- | --- |
| 姿态 | `反击姿态`、`盾墙`、`护卫架势` | 反击 / 护卫 / 防护窗口 |
| 资源 | `战意`、`狂怒` | 可叠层资源；狂怒满层转 `不倦狂暴` 占位 |
| 强化态 | `狂暴`、`全军突击`、`战神降临` | 短时增伤 / 减伤 / 团队节奏 |
| 团队防护 | `神恩庇护`、`神圣庇护`、`圣域祷言` 等 | 减伤、AC、豁免、临时生命窗口 |
| 被动态 | `火焰亲和`、`重甲祷法` | 供其他逻辑读取，本身不跳伤 |

完整 ID 列表与实现备注见 [`docs/buff_shared_table.md`](../docs/buff_shared_table.md)。

## 7. 修改流程

改 Buff 行为或新增状态时，按以下顺序：

1. 更新本文档（通用规则或 §4 核心状态）。
2. 若涉及职业 Feat，同步 `roguelike_feat_skill_fill_sheet.md` §8。
3. 更新 `config/data/buffs.json`（及关联 `skills.json` 描述）。
4. 再改 Lua：`battle_skill_status.lua`、`buff_effect_registry.lua`、`skill_effect_registry.lua` 等。
5. 同步 `docs/buff_shared_table.md`；必要时更新 `docs/buff_system_implementation.md`。
6. 跑相关 `bin/test_*.lua`；跨模块改动补 Web E2E。

## 9. 一页结论

```text
GOOD / BAD / CONTROL 三层实现
refresh 与 add 两套叠层语义
核心状态必须来源隔离
硬控跳过行动；霜冻 / 减速只铺垫不跳回合
DoT：中毒叠层跳伤；燃烧每回合反射豁免（成功移除、失败 1d4 继续）
标记：猎人印记减 AC/豁免；静电印记雷系兑现、雷暴清除
改 Buff：先 design/ 再 config/ 再 skills/，并同步 docs/
```
