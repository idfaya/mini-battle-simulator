# Roguelike Feat 树设计

## 1. 设计目标

把职业 feat 改成树形结构：等级只决定能走多少树点，build 走向由玩家在树上的选择决定。

- 与 [`class_system_design.md`](./class_system_design.md) §4.5 的 5e 画像（`primary_ability` / `spell_ability` / `armor_formula` / `save_proficiency`）对齐；low / mid / high 核心能力的节点级 SSOT 见本文档 §8。
- 等级 1 自动获得根节点，对应职业 low 核心被动；Lv3 必须从主干 T1（mid 核心主动）选；Lv5 必须从主干 T2（high 核心主动）选；Lv10 必须从满足前置的 capstone 中选 1 个；其余等级提供 1 自由点。
- build 走向由玩家在树上的分支选择决定。

## 2. 母技能映射

每个职业的核心 R / T1 / T2 节点都把效果挂到下表的母技能上，避免另起独立伤害链：

| 职业 | 母技能 |
| --- | --- |
| 战士 | 基础武器攻击 |
| 武僧 | 徒手打击 |
| 盗贼 | 基础武器攻击 |
| 游侠 | 远程基础攻击 |
| 圣骑 | 圣武打击 |
| 野蛮人 | 狂斧劈砍 |
| 法师 | 寒霜射线 |
| 术士 | 火焰弹 |
| 牧师 | 神圣火花 |
| 邪术师 | 邪能冲击 |

## 3. 一页结论

| 职业 | 核心定位 | 一句话定义 |
| --- | --- | --- |
| 战士 | 反击 / 护卫 | 敌方对你发动近战攻击后，攻击结算后立刻回手一次，并通过护卫线把伤害引到自己身上。 |
| 武僧 | 疾风连击 | 徒手打击为 `1d6`；每回合第一次徒手打击后必定对同一目标追加一次额外攻击，不要求命中，也不走概率；非首击不连击。 |
| 盗贼 | 偷袭 | 目标受控、被牵制或夹击成立时，基础武器攻击命中后追加伤害。 |
| 游侠 | 猎人印记 | 远程基础攻击命中后给目标挂上唯一印记，并在本回合第一次对其造成伤害时追加追猎伤害。 |
| 圣骑 | 圣疗 / 破邪斩 / 神圣灵光 | 初始先拿 `圣疗` 稳血线，随后用 `破邪斩` 做单体爆发，Lv5 再接入 `神圣灵光` 提供团队保护。 |
| 野蛮人 | 狂暴 | 完成基础攻击或受到攻击时自动进入狂暴；状态不叠层，期间受到物理伤害 `-2` 且所有攻击伤害 `+2`。 |
| 法师 | 霜冻 → 冻结 | 寒霜法术命中后挂霜冻，再用 `冻结新星` 与 `暴风雪` 把霜冻兑现成冻结控制与群体伤害。 |
| 术士 | 余烬点燃 | 火焰法术命中点燃敌人，并围绕已点燃目标兑现 `灰烬爆燃` 与 `烈焰风暴`。 |
| 牧师 | 神恩庇护 | 持续为队友提供第一层减伤，并在关键时刻抬血、清负面、撑团队圣域。 |
| 邪术师 | 静电印记 | 邪能冲击命中后挂上短时印记，再用 `雷链` 与 `雷暴` 收束印记收益。 |

## 4. 职业间区分原则与风险

### 4.1 职业间区分原则

- 法师走 `霜冻 → 冻结`，主轴是「无法移动的铺垫状态 / STUN」；邪术师走 `印记 → 雷链 / 雷暴`，主轴是「静电印记 + 弹射连锁」。两类「挂状态再兑现」的职业必须在外延上拉开。
- 术士的 `烈焰风暴` 围绕「已点燃」兑现；法师的 `暴风雪` 围绕「已霜冻」兑现。两者都不做无差别全屏高伤。
- 牧师是唯一以「友方目标决策」为主的法系职业，其能力不替代另三人的输出 / 控场职责。
- 战士反击、武僧连击、盗贼偷袭均不限制次数；平衡通过控制单次收益实现，不反向削成无触发感。
- 圣骑采用「神圣灵光」光环语义，主轴是 `AC / 豁免 / 范围`；牧师的减伤庇护与圣域祷言取高不叠加。
- 野蛮人不再维护狂怒层数；狂暴只通过 R / T1 / T2 节点驱动，进入与持续完全由触发条件决定。

### 4.2 风险

- 过度叠加 AC / 豁免 / 临时生命的常驻光环（圣骑灵光、牧师圣域），多职业并存时的常驻属性溢出。
- 状态来源覆盖：法师霜冻、术士点燃、邪术师印记、游侠印记同时存在时，必须保留来源标记，避免互相覆盖或重复兑现。
- 印记 / 点燃类被动若无来源隔离，多人同职业会出现重复兑现。
- `神恩庇护` 与 `圣域祷言` 的减伤必须取高不叠加；护卫架势的远程承担、护卫成功回血等窗口型保护必须收口在明确触发条件内。

## 5. Feat 树通用结构

节点类型：

- **根节点 R**：每职业 1 个，对应 low 核心被动。等级 1 自动获得，作为 fixed feat，不消耗自由点。
- **主干节点 T1**：对应 Lv3 mid 核心主动。第一次点时 `grant_skill = mid_slot`。
- **主干节点 T2**：对应 Lv5 high 核心主动。第一次点时 `grant_skill = high_slot`。
- **分支节点 B**：每职业 8~12 个可选小卡，提供数值 / 触发器加深。
- **合流节点 J**：必须先点过两条分支才能解锁的强化节点，承担「构筑收尾」的语义。
- **Capstone C**：每职业 2 个，全 Run 只能选 1 个。

## 6. 走树规则

- 每个非根节点至少有 1 个父节点已被点过才能选。
- 单节点只能点 1 次。
- 少数需要“多个父节点同时满足”的节点，使用 `prerequisites + requireAllPrerequisites = true` 表达；当前盗贼的 `J 诡诈·眩晕`、`C 致命偷袭`、`C 诡诈大师` 属于此类。
- 分支可设互斥组（mutex），通过 §8 落表中的 `choiceGroup` 字段在树形节点之间表达。
- 主干 T1 / T2 第一次点时 `grant_skill` 对应核心主动，后续合流节点对该主动做 `modify_skill`。
- Capstone 全 Run 只能选 1 个；选定后其它 capstone 节点不再出现在候选池。

## 7. 等级与点数表

| 等级 | 是否给点 | 限制 |
| ---: | :---: | --- |
| Lv1 | 自动获得 R | 无（fixed） |
| Lv2 | 1 自由点 | 无 |
| Lv3 | 1 受限点 | 必须从 T1 候选选 |
| Lv4 | 1 自由点 | 无 |
| Lv5 | 1 受限点 | 必须从 T2 候选选 |
| Lv6 | 1 自由点 | 无 |
| Lv7 | 1 自由点 | 无 |
| Lv8 | 1 自由点 | 无 |
| Lv9 | 1 自由点 | 无 |
| Lv10 | 1 受限点 | 必须从满足前置的 capstone 选 |

自由点可以走任何已解锁的 B / J 节点，前提是父节点已点过。

## 8. 每职业 Feat 树

### 8.1 战士 Fighter

`Lv1` 固定获得 `战士训练` 与 `R 回气基础`。`Lv3` 自动接入 `T1 反击基础`，`Lv5` 自动接入 `T2 护卫基础`。战士的早期节奏先用 `回气` 稳住血线，再在中段获得 `反击`，高段进入 `护卫` 团队保护窗口。

| --- | --- | --- | --- | --- |
| `R 回气基础` | — | `R` | 获得 `回气`：回复 `1d10 + 体质修正` 生命，每场 `1` 次 | `grant low 核心主动` |

## 10. Schema 与 feats.lua 对接

`BuildFeatDef`（位于 `config/tables/feats.lua` 顶部 EmmyLua 注释）需要新增以下可选字段：

- `prerequisites: integer[]` —— 父节点 feat id 列表，用于实现「至少有一个父节点已点过」的解锁判定。
- `requireAllPrerequisites: boolean` —— 为 `true` 时，`prerequisites` 中列出的父节点必须全部已点过；用于表达 `J / C` 合流节点的多父同时满足。
- `isRoot: boolean` —— 是否根节点 R，等级 1 自动获得，不消耗自由点。
- `trunk: "T1" | "T2" | nil` —— 主干位置；存在时 picker 在 Lv3 / Lv5 仅从该候选筛选。
- `isCapstone: boolean` —— 是否 capstone C；全 Run 只能选 1 个，picker 选定后清理同类候选。
- `treeSlot: "R" | "B" | "J" | "T1" | "T2" | "C" | nil` —— 树位语义，便于 UI / picker 排序与限制。

字段全部为可选；按节点类型逐个补齐即可。
