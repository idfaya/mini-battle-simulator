# Roguelike Feat 树设计

## 1. 设计目标

把职业 feat 改成树形结构：等级只决定能走多少树点，build 走向由玩家在树上的选择决定。

- 与 [`class_system_design.md`](./class_system_design.md) §4.5 的 5e 画像（`primary_ability` / `spell_ability` / `armor_formula` / `save_proficiency`）对齐；low / mid / high 核心能力的节点级 SSOT 见本文档 §8。
- 等级 1 自动获得根节点，对应职业 low 核心被动；Lv3 必须从主干 T1（mid 核心主动）选；Lv5 必须从主干 T2（high 核心主动）选；Lv10 必须从满足前置的 capstone 中选 1 个；其余等级提供 1 自由点。
- build 走向由玩家在树上的分支选择决定。

## 2. 母技能映射

每个职业的核心 R / T1 / T2 节点都把效果挂到下表的母技能上，避免另起独立伤害链：

| 职业 | 母技能 |
| --- | --- |
| 战士 | 基础武器攻击 |
| 武僧 | 徒手打击 |
| 盗贼 | 基础武器攻击 |
| 游侠 | 远程基础攻击 |
| 圣骑 | 圣武打击 |
| 野蛮人 | 狂斧劈砍 |
| 法师 | 寒霜射线 |
| 术士 | 火焰弹 |
| 牧师 | 圣火术 + 治愈真言 |
| 邪术师 | 邪能冲击 |

## 3. 一页结论

| 职业 | 核心定位 | 一句话定义 |
| --- | --- | --- |
| 战士 | 反击 / 护卫 | 敌方对你发动近战攻击后，攻击结算后立刻回手一次，并通过护卫线把伤害引到自己身上。 |
| 武僧 | 疾风连击 | 徒手打击为 `1d6`；每回合第一次徒手打击后必定对同一目标追加一次额外攻击，不要求命中，也不走概率；非首击不连击。 |
| 盗贼 | 偷袭 | 目标受控、被牵制或夹击成立时，基础武器攻击命中后追加伤害。 |
| 游侠 | 猎人印记 | 远程基础攻击命中后施加**自己的**印记（默认同游侠维持 1 个目标）；印记期间目标 AC 与敏捷豁免各 `-1`。 |
| 圣骑 | 圣疗 / 破邪斩 / 神圣灵光 | 初始先拿 `圣疗` 稳血线，随后用 `破邪斩` 做单体爆发，Lv5 再接入 `神圣灵光` 提供团队保护。 |
| 野蛮人 | 狂暴 | 完成基础攻击或受到攻击时进入狂暴（低阶每场 `1` 次，`狂暴精通` 取消次数限制）；不叠层，期间物理减伤 `-2`、伤害 `+2`。 |
| 法师 | 减速 → 冻结 | 寒霜法术命中后挂减速（降先攻），再用 `冻结新星` 与 `暴风雪` 把减速兑现成冻结控制与群体伤害。 |
| 术士 | 余烬点燃 | 火焰法术命中点燃敌人，并围绕已点燃目标兑现 `灰烬爆燃` 与 `烈焰风暴`。 |
| 牧师 | 圣火术 / 治愈真言 / 驱散 / 庇护 | Lv1 先用 `圣火术 + 治愈真言` 稳定输出与抬血，Lv3 接 `驱散亡灵`，Lv5 后再展开庇护线。 |
| 邪术师 | 静电印记 | 邪能冲击命中后挂上短时印记，再用 `雷链` 与 `雷暴` 收束印记收益。 |

## 4. 职业间区分原则与风险

### 4.1 职业间区分原则

- 法师走 `减速 → 冻结`，主轴是「减速铺垫（降先攻）+ 冻结硬控」；邪术师走 `印记 → 雷链 / 雷暴`，主轴是「静电印记 + 弹射连锁」。两类「挂状态再兑现」的职业必须在外延上拉开。
- 术士的 `烈焰风暴` 围绕「已点燃」兑现；法师的 `暴风雪` 围绕「已减速」兑现。两者都不做无差别全屏高伤。
- 牧师是唯一以「友方目标决策」为主的法系职业，其能力不替代另三人的输出 / 控场职责。
- 战士反击、武僧连击、盗贼偷袭均不限制次数；平衡通过控制单次收益实现，不反向削成无触发感。
- 圣骑采用「神圣灵光」光环语义，主轴是 `AC / 豁免 / 范围`；牧师的保护线统一收口为「祝福 / 援助」语义。
- 野蛮人不再维护狂怒层数；狂暴只通过 R / T1 / T2 节点驱动，进入与持续完全由触发条件决定。

### 4.2 风险

- 过度叠加 AC / 豁免 / 临时生命的常驻光环（圣骑灵光、牧师祝福术），多职业并存时的常驻属性溢出。
- 同目标同 `buffId` 仅一条 Buff 实例；重复施加刷新持续并覆盖 `caster`（猎人印记另用 `runtime.rangerMarks` 按来源判定）。多人同职业时后手刷新会改写归属，技能联动以「目标是否带状态」为准，不假设并行多实例。
- 印记 / 点燃类 Feat 的 `vs*` 加值只检测状态有无，不按 `caster` 分账；游侠 / 邪术师须用 `IsTargetMarkedBy` / 印记兑现次数限制防刷。
- 牧师的团队保护统一通过 `祝福术` 的短时豁免窗口与 `援助术` 的临时生命收口；不要再回到 `减伤 + 团队 AC + 临时生命` 混搭语义。

## 5. Feat 树通用结构

节点类型：

- **根节点 R**：每职业 1 个，对应 low 核心被动。等级 1 自动获得，作为 fixed feat，不消耗自由点。
- **主干节点 T1**：对应 Lv3 mid 核心主动。第一次点时 `grant_skill = mid_slot`。
- **主干节点 T2**：对应 Lv5 high 核心主动。第一次点时 `grant_skill = high_slot`。
- **分支节点 B**：每职业 8~12 个可选小卡，提供数值 / 触发器加深。
- **合流节点 J**：必须先点过两条分支才能解锁的强化节点，承担「构筑收尾」的语义。
- **Capstone C**：每职业 2 个，全 Run 只能选 1 个。

## 6. 走树规则

- 每个非根节点至少有 1 个父节点已被点过才能选。
- 单节点只能点 1 次。
- 少数需要“多个父节点同时满足”的节点，使用 `prerequisites + requireAllPrerequisites = true` 表达；当前盗贼的 `J 诡诈·眩晕`、`C 致命偷袭`、`C 诡诈大师` 属于此类。
- 分支可设互斥组（mutex），通过 §8 落表中的 `choiceGroup` 字段在树形节点之间表达。
- 主干 T1 / T2 第一次点时 `grant_skill` 对应核心主动，后续合流节点对该主动做 `modify_skill`。
- Capstone 全 Run 只能选 1 个；选定后其它 capstone 节点不再出现在候选池。

## 7. 等级与点数表

| 等级 | 是否给点 | 限制 |
| ---: | :---: | --- |
| Lv1 | 自动获得 R | 无（fixed） |
| Lv2 | 1 自由点 | 无 |
| Lv3 | 1 受限点 | 必须从 T1 候选选 |
| Lv4 | 1 自由点 | 无 |
| Lv5 | 1 受限点 | 必须从 T2 候选选 |
| Lv6 | 1 自由点 | 无 |
| Lv7 | 1 自由点 | 无 |
| Lv8 | 1 自由点 | 无 |
| Lv9 | 1 自由点 | 无 |
| Lv10 | 1 受限点 | 必须从满足前置的 capstone 选 |

自由点可以走任何已解锁的 B / J 节点，前提是父节点已点过。

## 8. 每职业 Feat 树

### 8.1 战士 Fighter

`Lv1` 固定获得 `战士训练` 与 `R 回气基础`。`Lv3` 自动接入 `T1 反击基础`，`Lv5` 自动接入 `T2 护卫基础`。战士的早期节奏先用 `回气` 稳住血线，再在中段获得 `反击`，高段进入 `护卫` 团队保护窗口。

| 节点 | 父节点 | 类型 | 效果 | 落点 |
| --- | --- | --- | --- | --- |
| `R 回气基础` | — | `R` | 获得 `回气`：回复 `1d10 + 体质修正` 生命，每场 `1` 次 | `grant low 核心主动` |
| `T1 反击基础` | `回气基础` | `T1` | 敌方对你发动近战攻击后，待该次攻击结算完成，立即对攻击者执行一次基础武器反击 | `grant mid_slot` |
| `T2 护卫基础` | `回气基础` | `T2` | 对应 `护卫架势`：期间 `AC +2`，替友军承担近战攻击，结算后对攻击者执行一次护卫反击 | `grant high_slot` |
| `B 回气熟练` | `回气基础` | `B` | `回气` 治疗额外 `+1d6` | `modify 回气` |
| `J 回气精通` | `回气基础 + 回气熟练` | `J` | 使用 `回气` 后，直到下回合开始前获得 `AC +2` | `modify 回气` |
| `C 回气大师` | `回气基础 + 回气精通` | `C` | `回气` 的可用次数从每场 `1` 次提升为每场 `2` 次 | `modify 回气` |
| `B 反击熟练` | `反击基础` | `B` | 反击 `hit +1` | `modify 反击` |
| `J 反击精通` | `反击基础 + 反击熟练` | `J` | 反击额外造成 `+1d6` 伤害 | `modify 反击` |
| `C 反击大师` | `反击基础 + 反击精通` | `C` | 敌方近战攻击你时，先执行反击，再结算该次敌方攻击；你的反击获得 `hit +1`、额外 `+1d6` 伤害 | `modify 反击时序` |
| `B 护卫熟练` | `护卫基础` | `B` | 护卫期间可替友军承担远程攻击；仅限攻击检定类远程伤害，不承担法术 AOE | `modify 护卫基础` |

| `B 连击基础` | `回气基础` | `B` | 你主动使用基础武器攻击命中时，立即对同一目标追加 `1` 次连击；反击与护卫反击不触发连击 | `modify 基础武器攻击` |
| `B 连击熟练` | `连击基础` | `B` | 连击 `hit +1` | `modify 连击` |
| `J 连击精通` | `连击基础 + 连击熟练` | `J` | 连击额外造成 `+1d6` 伤害 | `modify 连击` |
| `C 连击大师` | `连击基础 + 连击精通` | `C` | 若本次基础武器攻击击杀目标，则本次连击可改为攻击另一名目标；若未击杀，则连击仍攻击原目标 | `modify 连击目标规则` |

#### 猎人印记（`ranger_hunter_mark` / `890005`）规则

猎人印记由 §3.4 游侠技能链导出；语义见 [`buff_system_design.md`](./buff_system_design.md) §3.4、§4.3。以下为本节 Feat 落点细则。

- **触发**：每回合 `1` 次；远程基础攻击**命中**后即对目标施加**自己的**印记（与最终伤害是否 `> 0` 无关；未命中不触发）。槽位满时按 passive 规则替换最早印记。
- **持续**：默认 `2` 回合（当前回合 + 下回合）；`印记延续` 通过 `dotDurationDelta` 延长。
- **槽位**：默认同游侠同时维持 `1` 个自己的印记。
- **减益**：印记存在期间，目标 **AC `-1`、敏捷豁免 `-1`**，由 buff `value` 承载。
  - `印记熟练（classMods.vsMarkBonusDice=1d6）`：远程攻击命中**自己的**印记目标时附加 `+1d6`（基础攻击、二连射、箭雨等均生效）。
  - `印记精通（classMods.vsMarkBonusDice=1d10）`：远程攻击命中**自己的**印记目标时附加 `+1d10`（与印记熟练叠加）。
- **结算**：经 `BuildPassiveCommon.GetDefenderAcBonus` / `GetDefenderSaveBonus("dex")` 读取 `890005.value`。
- **联动**：`二连射`、`箭雨`、远程基础攻击等经 `vsMarkBonusDice` 读取印记加成，仅对**已被你标记**的目标生效。

#### 防守姿态（`ranger_defense_stance` / `80005102`）规则

- **基础**：`防守基础` 授予被动；`baseAcBonus` 经 `GetDefenderAcBonus` 常驻生效。
- **熟练**：攻击检定**命中**后（`DefBeforeDmg` 且 `attackHit=true`）激活 `onHitAcBonus`，持续至当前回合编号结束（`expireRound = 当前回合`）。
- **精通**：实际受到伤害后（`DefAfterDmg` 且 `damage>0`）激活 `onDamageReductionFlat`，在后续 `DefBeforeDmg` 中 flat 减伤，持续至当前回合结束。

## 10. Schema 与 feats.lua 对接

`BuildFeatDef`（位于 `config/tables/feats.lua` 顶部 EmmyLua 注释）需要新增以下可选字段：

- `prerequisites: integer[]` —— 父节点 feat id 列表，用于实现「至少有一个父节点已点过」的解锁判定。
- `requireAllPrerequisites: boolean` —— 为 `true` 时，`prerequisites` 中列出的父节点必须全部已点过；用于表达 `J / C` 合流节点的多父同时满足。
- `isRoot: boolean` —— 是否根节点 R，等级 1 自动获得，不消耗自由点。
- `trunk: "T1" | "T2" | nil` —— 主干位置；存在时 picker 在 Lv3 / Lv5 仅从该候选筛选。
- `isCapstone: boolean` —— 是否 capstone C；全 Run 只能选 1 个，picker 选定后清理同类候选。
- `treeSlot: "R" | "B" | "J" | "T1" | "T2" | "C" | nil` —— 树位语义，便于 UI / picker 排序与限制。

字段全部为可选；按节点类型逐个补齐即可。
